--------------------------------------------------------------------------------

  * Student Portal:        http://localhost:5000/student (or :3000/student)

3. HOW TO START THE APPLICATION (MANUAL 5-TAB METHOD)
--------------------------------------------------------------------------------

[TAB 1: DOCKER SERVICES (MONGODB + REDIS)]
Run once in the background:
  cd Cybotz-landing
  docker compose up -d

[TAB 2: WHATSAPP SERVER - PORT 8080]
Runs the WhatsApp Baileys automation engine. Generates QR code in terminal for linking.
Command:
  cd Cybotz-landing
  npx tsx server/run-whatsapp.ts

[TAB 3: BULLMQ WORKER]
Processes asynchronous message queues dispatched from booking operations.
Command:
  cd Cybotz-landing
  npx tsx server/worker.ts

[TAB 4: BACKEND API SERVER - PORT 5000]
Handles bookings, clash prevention, JWT authentication, blogs, comments, student sync, and curriculums.
Command:
  cd Cybotz-landing
  npx tsx server/index.ts

[TAB 5: FRONTEND WEB SERVER - PORT 3000]
Launches the interactive Cybotz website and image auto-compression watcher in dev mode.
Command:
  cd Cybotz-landing
  pnpm run dev

5. WHATSAPP AUTOMATION & QR AUTHENTICATION PROCEDURE
--------------------------------------------------------------------------------

- How to Authenticate WhatsApp Session (QR Code):
  1. Start the WhatsApp Server (`npx tsx server/run-whatsapp.ts`).
  2. If not logged in, an ASCII QR code will display directly in your terminal console.
  3. Open WhatsApp on your smartphone -> Settings / Menu -> Linked Devices -> Link a Device.
  4. Point your phone camera at the terminal QR code to scan and authorize.
  5. Once authenticated, the terminal logs: "✅ WHATSAPP CONNECTED & READY TO SEND MESSAGES!".
  6. Credentials persist automatically inside the `baileys_auth_session/` directory.

- WhatsApp API Key Authentication:
  - All endpoints (/sendText and /groups) require header 'x-api-key' matching WHATSAPP_API_KEY in .env.
  - The Express backend and BullMQ worker automatically attach this header.

- Session Reset & Re-authentication:
  If credentials corrupt or you switch numbers:
  1. Stop the WhatsApp runner (Ctrl+C).
  2. Delete the `baileys_auth_session` directory.
  3. Restart `npx tsx server/run-whatsapp.ts` and scan the newly generated QR code.

- Health Check & Group IDs:
  - Health check endpoint: http://localhost:8080/status (Public)
  - Group IDs endpoint:   http://localhost:8080/groups?apiKey=cybotz_wa_key_2026

6. ACCESS PORTALS, ROLES & STUDENT ENGINE
--------------------------------------------------------------------------------

- Access URLs:
  * Admin / Staff Portal:    http://localhost:5000/portal (or /admin or footer link)
  * Student Learning Portal: http://localhost:5000/student

- Role Hierarchy & Permissions:
  * `admin`: Full operations management (Bookings, Blogs, Curriculums, Gallery, Team Management, Student Sync).
  * `editor`: Content & event management (Blogs, Curriculums, Rescheduling bookings, Gallery, Comment Moderation).
  * `viewer`: Read-only access to view reservations and dashboard.
  * `student`: Dedicated Student Learning Portal (`/student`), post and edit own comments on blog articles. Cannot access administrative controls.

- Security Authentication:
  - Authenticates via JWT Bearer Token issued by `/api/admin/login` or `/api/student/verify-reset-otp`.
  - Token expires in 12 hours (admin/editor) or 30 days (student).

- Dedicated Student Learning Portal (/student):
  1. Section 1: My Blog Comments & Discussion Threads:
     - Lists all comments the student posted across all articles.
     - 1-Click direct redirect button ("Open Article") to that specific blog post.
     - Shows all reply interactions from other students/instructors with direct conversation deep links.
  2. Section 2: Active Curriculum Status & The Next Move:
     - Live progress percentage across enrolled STEM tracks (Drone Engineering, Robotics, IoT).
     - Active module milestone details (Step X of Y).
     - "The Next Move" callout box with target dates, required preparation tasks, and prep guide links.

- Blog Discussion & In-UI Conduct Policy:
  - Embedded directly below blog articles (no floating window required).
  - In-UI Conduct Notice: Displayed prominently above the comment box prohibiting vulgarity.
  - Real-Time Profanity Filtering on both client and server before database persistence.
  - Clean display: No "Student" badges/labels are shown next to comment author names.
  - Editors/Admins/Master can delete any comment; students can edit their own.

- Automated Excel / CSV Student Account Synchronizer:
  - Place `students.xlsx` or `students.csv` in `server/data/`.
  - Click "Sync Students" in the Admin Portal User Management tab (or `POST /api/admin/students/sync`).
  - Auto-normalizes phone numbers, generates clean usernames, and sets `mustChangePassword: true`.
  - Dispatches clean, emoji-free WhatsApp welcome notifications with portal access instructions.
  - Students set their permanent password on first login via a 6-digit WhatsApp OTP.

- Admin Portal Tabs & Features:
  1. Reservations Tab: View active bookings, reschedule session times, cancel reservations, batch clear, Google Calendar sync.
  2. Manage Blogs Tab: Create, edit, and publish rich markdown blog articles with code syntax highlighting.
  3. Curriculums Tab: Add, edit, or delete modular courses.
  4. Users Tab: Manage team accounts, OTP account creation, and 1-click "Sync Students" from Excel.
  5. Changelogs Tab: Comprehensive administrative audit trail.
  6. Gallery Tab: Upload and manage workshop/lab showcase photos with Sharp WebP compression.
